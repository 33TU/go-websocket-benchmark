# ews against gws, 10k connections, desktop

Run on 2026-09-17 with this fork at commit efb67e2: gws v1.10.2, ews v0.2.0,
Go 1.27.1 on Linux 7.2, AMD Ryzen 9 9950X3D, 16 cores. Servers pinned to
cores 0 to 5, six cores on the V-cache die, and the client to the eight
cores and their SMT siblings on the other die, so neither starves the other.
Two runs per server, alternating; both runs are shown. Same method as the
laptop run beside this file.

```sh
taskset -c 0-5 ./gws.server &
taskset -c 8-15,24-31 ./bench.client -f=gws -c=10000 -dc=2000 -en=2000000 -rate=true -rd=10
```

## BenchEcho

2,000,000 echoes of 1024-byte messages over 10,000 connections.

| server | TPS | CPU avg | memory avg | failed |
|---|---|---|---|---|
| gws | 744,433 / 745,709 | 373% / 368% | 173 / 171 MB | 0 |
| ews | 748,816 / 741,949 | 364% / 364% | 143 / 139 MB | 0 |

A tie on throughput and CPU; ews uses about 20 percent less memory, as on
the laptop.

## BenchRate

Each connection is offered 200 messages per second for 10 seconds, sent in
16 KiB batches; the client counts what comes back. EchoEER is echoes per
second per CPU percent.

| server | EchoEER | sent | received | dropped | CPU avg | memory avg |
|---|---|---|---|---|---|---|
| gws | 3,949 / 3,934 | 12.42M / 12.39M | 12.19M / 12.17M | 1.9% / 1.8% | 309% / 309% | 235 / 236 MB |
| ews | 9,822 / 9,842 | 19.91M / 19.90M | 19.91M / 19.90M | 0 | 203% / 202% | 168 / 210 MB |

The offered load is 20M messages, and ews took in all of it with nothing
dropped, on two thirds of gws's CPU. gws accepted 12.4M and dropped 1.9
percent. The efficiency ratio is 2.5 here against 1.8 on the laptop: with
six fast cores ews is bound by what the client offers rather than by the
server, so a higher send rate would widen its number further while gws's
stays where it is.

## Synchronous pair: gws_std against ews_sync

Both through net/http on every port, both writing each echo before the next
read, both handing the connection to a fresh goroutine and returning from the
handler. Same machine and method as above, two runs each.

| server | echo TPS | echo CPU | echo memory | rate EER | sent | dropped | rate memory |
|---|---|---|---|---|---|---|---|
| gws_std | 751,431 / 758,762 | 361% / 360% | 174 / 172 MB | 3,988 / 3,958 | 12.42M / 12.34M | 1.8% / 1.9% | 191 / 180 MB |
| ews_sync | 758,465 / 753,988 | 360% / 359% | 158 / 149 MB | 4,002 / 4,017 | 12.39M / 12.43M | 1.9% / 1.8% | 158 / 149 MB |

A tie, as on the laptop. The synchronous servers land where gws does in the
rate test, so the asynchronous ews server's lead is the Queue coalescing a
backlog into one writev, not the read side.
