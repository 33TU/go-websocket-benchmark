# The full suite, 10k and 30k connections, desktop

Run on 2026-09-17 with this fork at commit ddc02d3: ews v0.2.0, gws v1.10.2,
Go 1.27.1 on Linux 7.2, AMD Ryzen 9 9950X3D. Every framework in
`script/config.sh`, one server at a time pinned to cores 0 to 5, the client
pinned to the other die; 1024-byte payloads, 2,000,000 echoes, then the rate
test for 10 seconds. One run per cell, all in one sitting. A gws run before
the first cell and after the last checks that the machine held steady: it
measured 1,090,884 echo TPS and 5,649 EER at the start and 1,111,312 echo TPS and 5,739 EER at the end. The generated
reports with every column are in [suite-2026-09-17-9950x3d/](suite-2026-09-17-9950x3d/).

```sh
taskset -c 0-5 ./output/bin/$f.server &
taskset -c 8-15,24-31 ./output/bin/bench.client -f=$f -c=$c -b=1024 -dc=2000 -en=2000000 -rate=true -rd=10 -suffix=_${c}_1024_2000000
./output/bin/bench.client -r=true -suffix=_${c}_1024_2000000
```

## How to read the echo test

The client's echo loop takes a connection from a pool, writes one request,
waits for the reply and returns the connection, so each connection carries
one request at a time and the echo TPS is the connection count divided by
the round trip. Every well-built library ties on it, within the noise of a
single run, and the medians are queueing delay: the minimum for each server
is tens of microseconds.

## Notes

- On echo every well-built library ties, ews among them, and ews uses the
  least memory of the group at 10k.
- In the rate test at 10k every good server takes the whole offered load;
  the difference is CPU. ews does it on about 195 percent where the others
  need 330 to 350, which is the highest EchoEER by 1.7 to 1.8 times.
- The hertz servers ignore SIGTERM; the run script kills every server with
  SIGKILL between frameworks.
- An earlier run of this suite the same night measured every server before
  a 21-minute stall at about 745k echoes per second and every server after
  it at over a million, and a comparison run that morning showed the same
  745k. The cause of that slower machine state was not found; this file
  replaces both, measured in one sitting with the drift check above.
