# ews against gws, 10k connections

Run on 2026-09-16 with this fork at commit b94e6c3: gws v1.10.2, ews v0.2.0,
Go 1.27.0 on Linux 6.12, 13th Gen Intel Core i9-13900H, 20 threads. Servers
pinned to cores 0 to 5 and the client to 6 to 19 so neither starves the
other. Two runs per server, alternating; both runs are shown.

```sh
taskset -c 0-5 ./gws.server &
taskset -c 6-19 ./bench.client -f=gws -c=10000 -dc=2000 -en=2000000 -rate=true -rd=10
```

## BenchEcho

2,000,000 echoes of 1024-byte messages over 10,000 connections.

| server | TPS | CPU avg | memory avg | failed |
|---|---|---|---|---|
| gws | 491,386 / 491,663 | 423% / 424% | 173 / 176 MB | 0 |
| ews | 489,586 / 490,999 | 421% / 423% | 139 / 143 MB | 0 |

A tie on throughput and CPU; ews uses about 20 percent less memory.

## BenchRate

Each connection is offered 200 messages per second for 10 seconds, sent in
16 KiB batches; the client counts what comes back. EchoEER is echoes per
second per CPU percent.

| server | EchoEER | sent | received | dropped | CPU avg | memory avg |
|---|---|---|---|---|---|---|
| gws | 2,765 / 2,790 | 10.75M / 10.79M | 10.51M / 10.55M | 2.2% | 380% / 378% | 237 / 238 MB |
| ews | 5,026 / 5,013 | 19.90M / 19.88M | 19.90M / 19.88M | 0 | 396% / 397% | 214 / 256 MB |

The client sends as fast as each server accepts, so ews took in 1.85 times
as many messages, answered every one, and did so at 1.8 times the
efficiency per CPU point.

## Notes

- Above about 30,000 connections the client, built on nbio, becomes the
  bottleneck and the rate test stops measuring the server; quote 10k and
  30k, treat 50k as a stress test.
- The suite's default of 50,000 in-flight echoes swaps a 30 GB machine at
  128 KiB payloads; cap it with `-ec` for large-message runs.
- Echo round trips sit on the kernel floor for every well-built library,
  here as in ews's own benchmarks; the differences show up under load, in
  memory, and in compression, which this suite does not exercise.
