# ews against gws after ews PR #11, 10k connections, desktop

Run on 2026-09-27 with this fork pinned to ews commit 05cd001, the merge of
[ews PR #11](https://github.com/33TU/ews/pull/11) (the last message's size
reserved past `poolKeep` for fragmented assembly; `bufpool` handles so a
buffer's return does not allocate), against gws v1.10.2; Go 1.27.1 on Linux
7.2, AMD Ryzen 9 9950X3D. Same method and pinning as the
[2026-09-26 run](ews-vs-gws-2026-09-26-9950x3d.md): servers on cores 0 to 5,
the client on the other die, one run per cell, one sitting, gws before the
first cell and after the last as a drift check. Only the ews servers and gws
were rerun. The generated reports are in
[ews-vs-gws-2026-09-27-9950x3d/](ews-vs-gws-2026-09-27-9950x3d/).

This harness sends single-frame messages below ews's 1 MiB pool cap, which
neither change in PR #11 touches, so the expectation was no movement, and
that is what the run shows: every figure is within a run's spread of the
2026-09-26 one.

## BenchEcho, 10,000 connections, 256 KiB payloads

against a 4.2 GB/s loopback link; the link is the ceiling and the means and
tails are queueing in front of it, so read the CPU and memory columns.
